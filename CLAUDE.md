## Run / build
```bash
go build -o dscrd ./cmd/dscrd               # version comes from the committed VERSION file
go test ./...                               # includes the command-coverage meta-test
go test ./internal/commands/ -run TestX -v  # focused (never include TestZZ in a filtered run)
go run ./cmd/dscrd generate-skills          # regenerate skills/ after any command change
scripts/smoke.sh                            # live test against a real server (env-gated)
goreleaser release --snapshot --clean       # local dry-run only
```

## Conventions
- Code comments + test names: English. Docs: SPEC.md / CLAUDE.md in English; PLAN.md in zh-TW; README.md is human-facing.
- One file per command group under `internal/commands/`, paired `_test.go`; every leaf command must be exercised via `runCmd`/`markCovered` — `zz_coverage_test.go` fails otherwise.
- Command annotations drive skills and behavior: `discordEndpoint`, `write` ("true" → CAUTION + `--dry-run` support), `perms`, `intents`.
- API-backed write verbs MUST honor `--raw` and `--dry-run`; with a snowflake target, `--dry-run` must work without credentials (`clientAndChannel` / `clientAndGuild`). Local-only write verbs (the `auth` group) have no API response, so they honor `--dry-run` only, via `dryRunLocal`.
- Response parsing uses compact item types implementing `Concise()`; tests run against `httptest` servers via the `DSCRD_API_BASE` override.
- Test fixtures use scrubbed identifiers: `Alice` / `Bob`, snowflakes like `111111111111111111` (guild) / `222…2` (channel) / `333…3` (message) / `444…4` (user) / `555…5` (role). Never commit real names, tokens, or real IDs.
- Exit codes: `0` ok · `3` auth · `4` not found · `5` rate-limited · `1` other. Mappings in `internal/api/errors.go`.

## Workflow rules
- Bot token only (Discord ToS forbids user-token automation); never add user-token paths.
- Tokens live in `~/.config/dscrd/config.toml` (0600), AES-256-GCM at rest, key per `DSCRD_KEYRING_BACKEND`. Never print or log token strings or the encryption key.
- `TestNoForeignBranding` bans external-platform tokens in all repo text; keep all docs/comments self-contained and do not weaken that test.
- `VERSION` is the version SSOT. After changing it, run `go run ./cmd/dscrd generate-skills` and commit; merging the bump to `main` triggers the release (tag + goreleaser + npm publish). A `VERSION` bump is always its own standalone `chore(release): X.Y.Z` PR.
- After adding/removing a command or changing annotations, regenerate `skills/` (CI `skill` job guards drift).
- Do NOT run `goreleaser release` (without `--snapshot`) locally against the real remote.

## Discord-side traps
- Message search is per-guild only; a cold index returns 202/`110000` (the client auto-retries) and new messages take minutes to index.
- Reading message content and member lists require privileged intents (MESSAGE_CONTENT / GUILD_MEMBERS) toggled in the Developer Portal; API errors carry a `hint:` line when this is the likely cause.
- Bot DMs need a mutual server (`50007` otherwise); bots cannot list their DM channels.
- Embed-only messages have empty `content`; rendering must include `[embed: …]` excerpts (see `renderMessage`).
- Channel name resolution is case-insensitive first-match; prefer IDs in scripts (`#bot` text channel vs `#BOT` category both match "bot").
